Examples on Levante¶

Having installed plotcleo, the following instructions are intended to guide you through running each example using the bash scripts in scripts/levante/. See how the bash scripts work for an overview of these scripts.

Note: the GPU job script, scripts/levante/gpu.sh, chooses a build configuration which uses GPUs. It must therefore run on a node in the GPU partition of Levante (see here for documentation on Levante’s partitions).

Configure the Bash Scripts¶

Every example is run with the same job script, scripts/levante/cpu.sh (or scripts/levante/gpu.sh to use GPUs). Before using it for the first time, you will need to set the paths in the section at the top of the script marked paths (EDIT THESE FOR YOUR SITE):

export CLEO_PATH2CLEO="${CLEO_PATH2CLEO:-${SLURM_SUBMIT_DIR:-$(pwd)}}"
export CLEO_PYTHON="${CLEO_PYTHON:-${CLEO_PATH2CLEO}/.venv/bin/python3}"
export CLEO_YACYAXTROOT="${CLEO_YACYAXTROOT:-<PATH/TO/YACYAXT/INSTALL>}"

You will need to configure cpu.sh and gpu.sh in the following ways:

  • Set the path to your YAC and YAXT installations:

    replace <PATH/TO/YACYAXT/INSTALL> with the path to the directory containing a directory for each compiler (e.g. gcc/), each with your yac and yaxt directories inside (see how to install YAC and YAXT).

  • Use your Python version:

    by default CLEO_PYTHON is the Python interpreter in the .venv which uv creates in your Cleo directory. If you use a different one, replace this path with the path to your Python interpreter. (hint: if you used uv to install python for Cleo, you can find the interpreter path via uv python find.)

  • Set your Slurm options:

    replace <YOUR_ACCOUNT> and <YOUR_EMAIL> in the #SBATCH lines at the top of the job script with your project account and email address. You may also want to change e.g. the --time or --partition.

    Note: the number of threads each example uses is set by num_threads in its configuration file (e.g. 128 for the constant 2-D thermodynamics example), so make sure it is not larger than the job script’s --cpus-per-task.

Instead of editing the job script, you can also set these variables in your terminal, or add them to your .bashrc or .bash_profile file, before using the job script, e.g.

export CLEO_YACYAXTROOT=your/path/to/yacyaxtroot

The job script stops with an error if any of these paths are still set to their <...> placeholders. Note: unless you export CLEO_PATH2CLEO, it is the directory you submit the job script from, so then submit it from your Cleo directory.

You can optionally configure the job script in the following ways:

  • Choose which examples to run:

    edit the examples list in the configuration section of the job script. Each entry states an example, its build configuration and its compiler, e.g. "as2017 serial gcc". You can instead choose one example when you submit the job script (see below).

  • Choose your build configuration:

    choose which parallelism to utilise via the buildtype. The options are serial, threads, openmp or cuda. The default is openmp. Note: setting buildtype to cuda requires you to use the GPU job script, gpu.sh, and the gcc compiler.

  • Choose your compiler:

    choose which compilers to use via the compilername. The options are gcc or intel (both via MPI wrappers). Note: the cuda build configuration requires you use the gcc compiler.

  • Choose your build directory:

    by default each example is built in its own directory inside your Cleo directory, e.g. the Arabas and Shima 2017 example in [CLEO_PATH2CLEO]/build_adia0d/as2017/. To use a different directory, set CLEO_PATH2BUILD in the job script’s optional settings (or export it) to that exact directory. Because every example would then share it, this only works when you run a single example.

  • Build from scratch:

    delete the example’s build directory, e.g. rm -rf [CLEO_PATH2CLEO]/build_const2d, before configuring Cleo with CMake again, e.g. after changing your compiler or build configuration.

Execute the Bash Scripts¶

From your Cleo directory, submit the job script to Slurm:

$ sbatch scripts/levante/cpu.sh [steps] [example] [buildtype] [compilername]

(or gpu.sh in place of cpu.sh to use GPUs). Submit the job script from your Cleo directory, because this is how the job script finds Cleo, or export CLEO_PATH2CLEO first.

All the arguments are optional:

  • steps: a comma-separated list of the steps to do, configure, compile, inputs, run and plot, or all (the default) for all of them (see running the examples).

  • example: the example to run. If it is not given, every example in the job script’s examples list is run.

  • buildtype and compilername: the build configuration and compiler for the example. If they are not given, the defaults for Levante are used, except that gpu.sh always uses the cuda build configuration.

For example, to submit a job which builds Cleo, compiles the executable, and runs and plots the Arabas and Shima 2017 example:

$ sbatch scripts/levante/cpu.sh all as2017

The Examples¶

Adiabatic Parcel

The examples, as2017.py and cuspbifurc.py, in examples/adiabaticparcel/ are for a 0-D model of a parcel of air expanding and contracting adiabatically with a two-way coupling between the SDM microphysics and the thermodynamics. The setup mimics that in Arabas and Shima 2017 section 7 [Arabas and Shima, 2017]. Note: due to numerical differences, the conditions for cusp bifurcation and the plots will not be exactly identical to this reference.

a) Arabas and Shima 2017

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all as2017

The plot produced, by default called ${CLEO_PATH2CLEO}/build_adia0d/as2017/bin/as2017fig.png, should be similar to figure 5 from Arabas and Shima 2017 [Arabas and Shima, 2017].

b) Cusp Bifurcation

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all cuspbifurc

The plots produced, by default called ${CLEO_PATH2CLEO}/build_adia0d/cuspbifurc/bin/cuspbifurc_validation.png and ${CLEO_PATH2CLEO}/build_adia0d/cuspbifurc/bin/cuspbifurc_SDgrowth.png illustrate an example of cusp bifurcation, analagous to the third column of figure 5 from Arabas and Shima 2017 [Arabas and Shima, 2017].

Box Model Collisions

These examples, shima2009.py and breakup.py, in examples/boxmodelcollisions/ are for a 0-D box model with various collision kernels. The setup mimics that in Shima et al. 2009 section 5.1.4 [Shima et al., 2009]. Note: due to the randomness of the initial super-droplet conditions and the collision algorithm, each run of these examples will not be completely identical, but they should be reasonably similar, and have the same mean behaviour.

The Collision Kernels:

Golovin

The shima2009.py example models collision-coalescence using Golovin’s kernel.

The plot produced, by default called ${CLEO_PATH2CLEO}/build_colls0d/shima2009/bin/golovin_validation.png, should be similar to Fig.2(a) of Shima et al. 2009 [Shima et al., 2009].

Long

The shima2009.py example models collision-coalescence using Long’s collision efficiency as given by equation 13 of Simmel et al. 2002 [Simmel et al., 2002].

The plot produced, by default called ${CLEO_PATH2CLEO}/build_colls0d/shima2009/bin/long_validation_[X].png, should be similar to Fig.2(b) of Shima et al. 2009 [Shima et al., 2009].

Low and List

The breakup.py example models collision-coalescence-rebound-breakup using the hydrodynamic kernel with Long’s collision efficiency as given by equation 13 of Simmel et al. 2002 [Simmel et al., 2002], and the coalescence/breakup/rebound probability from Low and List 1982(a) [Low and List, 1982] (see also McFarquhar 2004 [McFarquhar, 2004]). If breakup occurs, a constant number of fragments is produced.

This example produces a plot, by default called ${CLEO_PATH2CLEO}/build_colls0d/breakup/bin/lowlist_validation.png.

Szakáll and Urbich

The breakup.py example models collision-coalescence-rebound-breakup using the hydrodynamic kernel with Long’s collision efficiency as given by equation 13 of Simmel et al. 2002 [Simmel et al., 2002], and the coalescence/breakup/rebound probability from Szakáll and Urbich 2018 [Szakáll and Urbich, 2018]. If breakup occurs, a constant number of fragments is produced.

This example produces a plot, by default called ${CLEO_PATH2CLEO}/build_colls0d/breakup/bin/szakallurbich_validation.png.

Testik and Straub

The breakup.py example models collision-coalescence-rebound-breakup using the hydrodynamic kernel with Long’s collision efficiency as given by equation 13 of Simmel et al. 2002 [Simmel et al., 2002], and the coalescence/breakup/rebound probability based on section 4 of Testik et al. 2011 (figure 12) [Testik et al., 2011] (first proposed in [Testik, 2009]), as well as coalescence efficiency and number of fragements produced from Straub et al. 2010 and Schlottke et al. 2010 respectively ([Schlottke et al., 2010], [Straub et al., 2010]).

This example produces a plot, by default called ${CLEO_PATH2CLEO}/build_colls0d/breakup/bin/testikstraub_validation.png.

Running the Box Model Collisions Examples:

a) Shima et al. 2009

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all shima2009

By default the golovin executable and two examples using the long executable will be compiled and run. You can change this by editing --kernels golovin long1 long2 in the shima2009 entry of scripts/common/examples.sh.

Golovin

This example models collision-coalescence using Golovin’s kernel.

The plot produced, by default called ${CLEO_PATH2CLEO}/build_colls0d/shima2009/bin/golovin_validation.png, should be comparable to Fig.2(a) of Shima et al. 2009 [Shima et al., 2009].

Long1 and Long2

These examples model collision-coalescence using Long’s collision efficiency as given by equation 13 of Simmel et al. 2002 [Simmel et al., 2002]. The two examples use almost identical initial conditions and collision timesteps, as in Shima et al. 2009 [Shima et al., 2009].

The plots produced, by default called ${CLEO_PATH2CLEO}/build_colls0d/shima2009/bin/long_validation_1.png and ${CLEO_PATH2CLEO}/build_colls0d/shima2009/bin/long_validation_2.png, should be comparable to Fig.2(b) and Fig.2(c) of Shima et al. 2009 [Shima et al., 2009].

b) Breakup

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all breakup

By default kernels including collision-coalescence, breakup and rebound will be compiled and run. You can change this by editing --kernels long lowlist szakallurbich testikstraub in the breakup entry of scripts/common/examples.sh.

Divergence Free Motion

This example is run from the examples/divfreemotion/divfree2d.py script.

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all divfree2d

This example plots the motion of super-droplets without a terminal velocity in a 2-D divergence free wind field. It produces a plot showing the motion of a sample of super-droplets, by default called ${CLEO_PATH2CLEO}/build_divfree2d/bin/divfree2d_motion2d_validation.png. The number of super-droplets in the domain should remain constant over time, as shown in the plot produced and by default called ${CLEO_PATH2CLEO}/build_divfree2d/bin/divfree2d_maxnsupers_validation.png.

3-D Thermodynamics From File (CPU only)

Note: currently these examples are not GPU compatible, therefore they can only be run with ``cpu.sh``, not ``gpu.sh``.

The examples, fromfile.py and fromfile_irreg.py, in examples/fromfile/ and examples/fromfile_irreg/ are for a 3-D domain with time varying thermodynamics read from binary files. The fromfile_irreg.py example uses an irregular 3-D grid. These examples run the executable with MPI via srun, by default with 4 MPI processes (--ntasks=4 in their entries of scripts/common/examples.sh).

a) Regular Grid

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all fromfile

The plots produced, by default called ${CLEO_PATH2CLEO}/build_fromfile/bin/ntasks4/fromfile_motion2d_validation.png and ${CLEO_PATH2CLEO}/build_fromfile/bin/ntasks4/fromfile_maxnsupers_validation.png, show the motion of a sample of super-droplets and the number of super-droplets in the domain over time.

b) Irregular Grid

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all fromfile_irreg

The plots produced are analagous to the regular grid example’s, by default in ${CLEO_PATH2CLEO}/build_fromfile_irreg/bin/ntasks4/.

3-D Bubble (CPU and GCC only)

Note: currently this example is not GPU compatible, therefore it can only be run with ``cpu.sh``, not ``gpu.sh``. Additionally, this example is not yet compatible with intel compilers on Levante, therefore it can only be run with ``gcc``, not ``intel``.

This example is run from the examples/bubble3d/bubble3d.py script. It couples Cleo to the dynamics of ICON’s bubble test case via YAC, so it requires Cleo to be built with the gcc compiler and YAC and YAXT to be installed. Unlike the other examples, the input files / output files directories are set independently from the build directory, through path2experiment=[...] in the bubble3d entry of scripts/common/examples.sh. This is so that the structure of the example’s build vs. input/output directories can be analogous to ICON’s. Additionally, this example reads the ICON grid and data files from the directory given by path2iconfiles, and copies the YAC coupling configuration from src_yac_config_filename; both of these, along with path2experiment, are also set in the bubble3d entry of scripts/common/examples.sh. You will need to edit these paths to point to your own bubble experiment and ICON grid/data directories on Levante.

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all bubble3d

Plots of the super-droplets’ motion and of the thermodynamics are produced, by default called ${CLEO_PATH2CLEO}/build_bubble3d/bin/bubble_motion.png and ${CLEO_PATH2CLEO}/build_bubble3d/bin/bubble_[variable].png.

Roughpaper → Towards Your Own Experiment

In CLEO/roughpaper we provide a source of inspiration for you to run your own experiment with Cleo. roughpaper is not an example with a reference solution, but it acts analogously and demonstrates most of the settings you can choose from when designing your own experiment. See our tutorial for more information on how to create your own experiment and how roughpaper can be useful for that.

roughpaper is not in the job scripts’ default examples list, however, if you wish to do so, you can run the roughpaper setup with Cleo’s bash scripts just like you would for an example. roughpaper builds and runs the executable cleocoupledsdm from roughpaper/src/main.cpp with the configuration file roughpaper/src/config/config.yaml. Its input files are made by roughpaper/roughpaper_inputfiles.py and the run is driven by roughpaper/roughpaper.py, all in an analogous way to Cleo’s actual examples.

  1. Configure the bash scripts.

  2. Submit the job script, e.g. from your Cleo directory:

$ sbatch scripts/levante/cpu.sh all roughpaper

To adapt the roughpaper setup, edit roughpaper/src/main.cpp, roughpaper/src/main_impl.hpp, roughpaper/src/config/config.yaml, roughpaper/roughpaper.py, and roughpaper/roughpaper_inputfiles.py. If your new roughpaper executable uses different coupled dynamics (e.g. cvode or yac), also change -DCLEO_COUPLED_DYNAMICS in the roughpaper entry of scripts/common/examples.sh and build from scratch (delete your build directory first). Again, rather than edit roughpaper, we recommend you build your own experiment as explained by the tutorial.

Figures of the initial conditions are saved by default in ${CLEO_PATH2CLEO}/build_roughpaper/bin/ and the output dataset is ${CLEO_PATH2CLEO}/build_roughpaper/bin/SDMdata.zarr. No plots of the results are made.
